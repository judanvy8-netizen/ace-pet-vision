# ACE — 반려동물 사진 탐지·품종 분류

기본 제공 05번 프로젝트의 **입력 → YOLO 탐지 → 개수 집계 → 저장** 흐름에 품종 분류를 추가했습니다.
**교사의 추가 지시:** 이번 팀 프로젝트에서는 기본 명세서에 없는 **개·고양이 37품종 분류도 필수 구현 목표**로 삼습니다. 단순 탐지 결과만으로 완성이라고 판단하지 않습니다.
사진은 기존 `data/images`의 20장을 사용합니다. 대용량 압축파일의 사진은 이번 변경에서 넣지 않았습니다.

## 팀 역할 및 발표 설명 범위

카카오톡 대화에서 정한 **7명 역할 분담**에 따라, 각 담당자가 설명할 수 있어야 할 코드와 검증 주제를 정리합니다. 아래는 **담당 분야와 설명 준비 범위**이며 개인별 구현·수정 완료 기록은 아닙니다.

| 담당 분야 | 설명할 파일·함수 | 발표에서 설명할 원리 |
|---|---|---|
| 조장·통합 (1명) | `source/main.py:main` | 사진 읽기 → YOLO 탐지 → 37품종 분류 → 결과 저장 전체 흐름 |
| 입력 데이터 (1명) | `data/metadata.csv`, `shared/common.py:image_files`, `read_image`, `read_photo_sources` | 사진·품종·출처, 경로 설정 및 입력 오류 처리 |
| AI 검출·분류 (2명) | `shared/common.py:yolo`, `yolo_rescue`, `yolo_strong`, `shared/pet_model.py:BreedClassifier`, `shared/fusion.py` | YOLO와 ResNet50의 차이, 종 판정 충돌 및 REVIEW |
| 시각화·결과 저장 (1명) | `shared/visualizer.py:annotate`, `shared/common.py:save_image`, `save_csv` | 박스·라벨·개수 표시와 결과 이미지·CSV 저장 |
| 검증·오류 분석 (1명) | `tests/test_pipeline.py`, `tests/test_species_fusion.py`, `data/ground_truth.csv` | 중복·오탐·미탐 사례, 수동 정답과 자동 테스트의 차이 |
| 문서·시연 (1명) | `README.md`, `개발_과정_및_수정_기록.md`, `카카오톡_일별_회의록.md` | 과제 목적·개발 흐름·시연·한계 설명 |

기본 코드의 `yolo, image_files, read_image, save_image, save_csv`를 사용하고, 품종 분류·마릿수 표시·정답 비교만 추가합니다.
현재 저장소 안에 `shared`를 함께 두므로, `main.py`는 프로젝트 루트를 Python 경로에 추가합니다.

## 실행

처음에는 Python 3.11(64비트)을 설치하고 `setup.bat`을 실행합니다. IntelliJ의 Python SDK와 Module SDK는 `.venv\Scripts\python.exe`로 선택합니다.
이미 준비했다면 **`source/main.py` 우클릭 → Run 'main'** 또는 아래 명령만 실행하세요.

```powershell
.\run.bat
```

**IntelliJ에서 실제 모델 확인:** 프로젝트 루트(예: `C:\KSW\ace-pet-vision`)에 GitHub 최신 파일을 반영하고, Python 3.11의 `.venv\Scripts\python.exe`를 Python SDK로 선택합니다. `source/main.py`를 Run 하되 작업 디렉터리를 프로젝트 루트로 설정하세요. 첫 실행에는 인터넷 연결이 필요합니다.

필요하다면 `run.bat --prepare-models`로 YOLO11n·YOLO11s·YOLO11m·ResNet50 가중치 다운로드·해시 검증을 미리 확인할 수 있습니다. 하지만 **실제 사용은 `main.py`를 그냥 실행하는 것만으로 충분**합니다. 모델이 없는 경우 필요한 가중치를 자동으로 받습니다. 그 다음 `run.bat --input data/images/03_dog_beagle.jpg --limit 1`로 **실제 품종 모델까지** 단일 사진을 테스트하세요. `outputs/pet_counts.csv`, `outputs/pet_breeds.csv`, `outputs/03_dog_beagle_pets.jpg`가 생성되는지 확인합니다. 이상이 없다면 `run.bat --limit 0`으로 20장을 검사합니다. Windows 배치 파일의 `pause`는 정상 동작이며, IntelliJ에서 직접 실행하는 경우에는 추가 인수 없이 기본 20장을 처리합니다.

기본 입력은 `data/images`, 기본 처리 수는 처음 20장입니다. `--limit 0`은 전체입니다.

### 자동 미탐지 보완 (기본 실행에 포함)

**추가 명령이나 별도 결과 폴더는 필요하지 않습니다.** IntelliJ에서 `source/main.py`를 Run 하거나 프로젝트 루트에서 `run.bat`만 실행하면 모든 사진에 동일한 자동 처리 규칙이 적용됩니다.

1. YOLO11n으로 기본 탐지 → 동물 박스가 있으면 37품종 ResNet50 분류
2. 탐지 0마리면 YOLO11s로 재검사
3. 그래도 0마리면 YOLO11s 고해상도 1280·TTA로 **자동** 재검사 (예전 `--deep-rescue` 별도 지정 불필요)
4. 그래도 0마리면 YOLO11m으로 전신 이미지와 일부 확대 이미지를 **자동** 재검사. 이 단계에서는 COCO가 개·고양이를 곰/양/말/소 등 다른 동물로 잘못 표시했는지도 확인하고, 37품종 모델로 후보를 재검토
5. 탐지 결과는 예전과 똑같이 `outputs/`의 **기존 파일명**을 사용합니다.

YOLO11m 가중치는 실제 필요해지는 순간에만 다운로드합니다(약 41MB). 일반적인 사진에는 경량 모델만 사용합니다. CPU에서는 미탐지 사진 재검사가 느릴 수 있습니다. **다른 동물 클래스를 품종 모델로 재평가한 결과는 `review_detection`으로 표시하고, 마릿수 오차 평가에서는 제외합니다.** 실제 YOLO 박스가 없는 경우 임의로 박스를 만들지 않습니다.

**최신 실사진 확인(2026-10-28):** 04번 벵갈은 사용자가 해결 완료로 확인했습니다. 08번 치와와는 YOLO가 개를 탐지했지만 ResNet50의 Chihuahua 품종 점수가 약 38.3%로 낮습니다. 16번 사모예드는 YOLO가 원래 `bear`로 인식한 박스를 ResNet50이 `Samoyed` 약 82.4%로 판단해 `review_detection`으로 기록했습니다. 19번 스핑크스는 YOLO의 `dog` 판단을 ResNet50의 `Sphynx` 약 94.9% 증거로 교정해 `Cats: 1`로 표시하지만 종 충돌 이력은 남깁니다. **이 수치는 모델의 예측 점수이지 실측 정확도가 아닙니다.**

`--single-pet-review`는 연구·검토용 수동 옵션이며 기본 실행에 포함되지 않습니다. 이 옵션은 동물 1마리를 사람이 확인한 사진에서 전체 이미지를 품종 분류기에 넣을 뿐, **YOLO 객체 검출 성공을 뜻하지 않습니다.**

사진 한 장: `.\run.bat --input data/images/03_dog_beagle.jpg`.
탐지 기준 비교: `.\run.bat --conf 0.5`.
기존 `--samples` 명령도 같은 20장 사진을 사용합니다.

## 모델

- 1차 탐지: `shared/models/yolo11n.pt` (CPU용 경량 모델)
- 2차 탐지: `shared/models/yolo11s.pt` (1차 0마리일 때만 실행; 약 19MB)
- 최종 재검사: `shared/models/yolo11m.pt` (고해상도 YOLO11s도 실패했을 때만 실행; 약 41MB)
- 품종: `shared/models/oxford-pets-resnet50.pth`

예전 프로젝트 `models/`에 같은 모델이 있으면 검증 후 새 위치로 복사해 재사용합니다. 기존 파일은 삭제하지 않습니다.
없으면 첫 실행 때 모델 파일만 자동 다운로드합니다. Oxford 원본 사진을 받을 필요는 없습니다.
Python 3.11·Ultralytics·OpenCV·CPU 실행을 사용하며 품종 분류에는 PyTorch·torchvision·Pillow를 추가 사용합니다.

## 결과

`outputs`를 펼치면 결과가 바로 보입니다.

```text
outputs/
├─ pet_counts.csv
├─ pet_breeds.csv
├─ 01_cat_abyssinian_pets.jpg
├─ 02_dog_basset_hound_pets.jpg

```

사진 위쪽에 Dogs/Cats 수, 동물마다 박스·품종 후보·점수를 표시합니다. 점수가 낮거나 종이 불일치하면 보류합니다.

### 두 AI 모델의 판단 비교 및 품종·종 오류 수정

YOLO는 **동물 위치와 cat/dog 클래스**, ResNet50은 **37개 품종 확률**을 산출합니다. 기존 구현은 YOLO의 개/고양이 종을 그대로 최종 개수에 사용하여, Sphynx 95%로 분류했는데 Dogs:1로 표기하는 오류가 있었습니다.

현재는 ResNet의 **전체 최고 품종 점수 85% 이상 + 해당 종의 확률 합계 90% 이상**으로 강하게 반박할 때에만 종을 교정합니다. 예: YOLO dog / ResNet Sphynx 95% → Cats:1. 단, 모델 간 충돌은 `review_species`로 기록하며 완전히 검증된 정답이라고 주장하지 않습니다.

반대로 YOLO dog / ResNet 전체 1위 Bengal 33% 같은 불확실한 경우에는 YOLO dog 판단을 유지하고 **개 품종 안에서 가장 높은 후보**를 보여줍니다. 품종 확률을 종별로 재정규화해 점수를 부풀리지 않습니다. 저신뢰·종 충돌 사진만 좌우반전 및 주변 영역을 추가 평가합니다.

이제 `outputs/pet_breeds.csv`에서 `yolo_label`(YOLO 원래 클래스), `detection_confidence`, `resnet_top_breed`, `resnet_top_confidence`, `resnet_species`, `resnet_species_mass`, `top3_global`, `top3_species`, `tta_used`, `reason`, `species`(최종 종류)를 **같은 행에서 비교**할 수 있습니다. 별도 실행 명령이나 결과 폴더는 필요 없습니다.

**검증 주의:** 사진 04의 Bengal 약 50% REVIEW는 실제 점수가 50% 미만인데 화면이 정수 반올림했을 수 있습니다. 이제 리뷰 점수는 소수 첫째 자리까지 표시합니다. 16 Samoyed의 YOLO 다른 동물 분류는 `review_detection`으로 기록하고 원래 라벨도 CSV에 표시합니다. 실제 사진의 수정 성공 여부는 IntelliJ에서 재실행해 확인해야 합니다.

**중복 탐지 보정:** 같은 동물의 전신·얼굴 박스처럼 크게 겹치는 박스는 한 마리로 셉니다. 실제 동물 두 마리가 겹친 사진은 수작업 검증이 필요합니다.
**미탐지 보완:** YOLO11n이 0마리인 사진만 YOLO11s·고해상도 TTA·YOLO11m 확대 검사 순서로 자동 재검사합니다. 기본 `main.py` 실행만으로 동작하며 새 결과 폴더는 만들지 않습니다. 실제 검출 개선은 사진별로 확인해야 하고, 실패 시 결과를 임의로 1마리로 바꾸지 않습니다.
`pet_counts.csv`에는 사진별 cat/dog 수, 정답과 개수 오차, 처리 상태 및 사용 탐지 모델(`detector`)이 기록됩니다. 사진 출처는 **`source_url` 열**에 나타나며 `data/metadata.csv`의 `source_page` 주소를 가져옵니다. 출처가 없는 사진은 빈칸으로 표시합니다.
`pet_breeds.csv`에는 동물별 품종 후보가 기록됩니다. 오류는 `errors.log`에서 확인합니다.

같은 이름의 결과는 다시 실행하면 갱신합니다. 이전 결과를 보관하려면 복사하거나 `--output outputs/experiment_02`로 별도 경로를 지정하세요.
현재 실행 결과는 CSV에 기록된 파일 기준으로 확인합니다. 이전 버전의 결과 폴더·설정 파일은 자동 삭제하지 않습니다.
원본 사진은 수정하지 않으며, 결과 이미지 위쪽에 마릿수 표시 여백을 추가합니다. 박스 좌표는 방향을 반영한 원본 사진 기준입니다.

## 정답과 실습

`data/ground_truth.csv`의 `actual_cat`, `actual_dog`에 **사람이 확인한 진짜 개수만** 입력하세요. 0마리는 `0`, 확인 전에는 빈 칸입니다.
실행 결과의 `cat_error`, `dog_error`는 |예측 수 − 실제 수|이며 미작성 정답이나 처리 실패에는 계산하지 않습니다.
`test_cases.csv`에 고양이·개·둘 다·동물 없음·가림·잘못된 입력의 결과를 기록하세요.
각자 수정 1건, 함수 1개 설명, 실패 사례 3개와 원인 분석을 준비합니다.
모델의 검출 수·품종은 정답을 보장하지 않습니다. 기존 사진에서도 중복 탐지·미탐이 있으며, 품종 후보 점수는 정확도가 아닙니다. **지원하지 않는 품종(예: 골든 리트리버)이나 혼합견도 지원되는 37품종 중 하나로 잘못 출력될 수 있습니다.** 실제 마릿수·품종 정확도는 수작업 검증 전까지 확인되지 않았습니다.

#### 1. 무엇을 만들기로 했나?

교사 원본 과제는 사진 속 **개/고양이 탐지·개수 계산·박스 표시·CSV 저장**이며, Python 3.11·Windows CPU·YOLO11n 사용이 기본입니다. 이후 교사의 **구두 추가 지시**에 따라 단순 개·고양이 구별을 넘어 **37개 품종 분류**를 필수 확장 기능으로 채택했습니다. 원본 Markdown에 품종 분류가 없는 것은 이 때문입니다.

**범위:** 우선 사진 파일 입력 → 사진 속 개·고양이 위치 찾기 → 영역별 37품종 후보 추론 → 결과 이미지·CSV 저장. 카메라·GUI는 후순위. Oxford-IIIT Pet 37품종(고양이 12, 개 25) 범위 밖인 골든 리트리버는 지원 품종이라고 주장하지 않습니다.

#### 4. 기술적 선택의 근거

1. **탐지와 품종 분류를 분리:** 사진 하나의 ResNet 품종 분류만으로는 여러 개체 위치·개수를 결정할 수 없습니다. YOLO 박스를 잘라 품종 모델에 전달합니다.
2. **중복 박스 병합:** 얼굴/몸통이 각각 별도 박스로 나오는 사례가 발생해 교집합/합집합 비율(IoU)과 작은 박스 포함률을 확인합니다. 실제로 동물이 서로 겹친 사진에서는 오병합 가능성이 있으므로 사람 검증이 필요합니다.
3. **미탐일 때만 무거운 검사:** YOLO11s와 TTA를 항상 쓰면 구형 Windows CPU에서 느려집니다. 검출 실패 경우에만 추가 실행합니다.
4. **닫힌 37품종 분류의 한계:** ResNet은 37개 중 후보를 강제로 고르므로, 지원 밖 품종 또는 동물이 없는 사진에서도 틀린 답을 낼 수 있습니다. 전체 이미지 분류는 반드시 `review_only`로 표시해 탐지 성공률에 포함하지 않습니다.
5. **사진 출처 열:** 출처를 결과와 함께 표시해 자료 제공자·사용 권한을 추적할 수 있도록 합니다. 출처가 없는 사진은 임의로 채우지 않습니다.

#### 5. 검증 결과·남은 과제

- **모의 단위/통합 테스트:** 기존 13개에 자동 고해상도 재검사·YOLO11m 확대 검사 경로·확대 박스 좌표 복원 테스트 3개를 추가해 **16개 통과**. 검출·분류 모델은 모의 객체를 사용했으므로 **실제 37품종 정확도나 16번 검출 성공을 뜻하지 않음**.
- **사용자 확인 결과:** 05·07번 중복 문제 해결, 19번 추가 검사는 탐지 성공, 16번은 이전 재검사까지 여전히 0마리.
- **다음 실험:** IntelliJ에서 `source/main.py`를 **그냥 Run**하여 16번 사모예드 결과(`outputs/16_dog_samoyed_pets.jpg` 및 CSV의 `detector`) 확인. 자동 YOLO11m·확대 검사도 0마리라면 미탐 사례로 기록하고 모델 성능 개선을 별도 검토. 파일명이나 정답표로 예측을 꾸미지 않음.
- **평가 자료:** `data/ground_truth.csv`의 20장 실제 개수, `test_cases.csv`의 관찰 결과, 동물 없음·혼합/가림 사례, 실패 사례 3개 이유 및 조건을 **사람이 확인하여 기록**해야 함.
- **발표 윤리:** 조장이 통합 구현한 코드라도 팀원별로 실제로 맡아 설명·수정·테스트한 내용을 구별해 제출합니다.

#### 6. IntelliJ에서 실행하는 방법 — 별도 옵션이나 결과 폴더 불필요

프로젝트 `C:\KSW\ace-pet-vision`을 IntelliJ에서 열고 `source/main.py` 우클릭 → **Run 'main'** 하면 기본 사진 20장을 자동 분석합니다. 또는 터미널에서 다음 두 명령만 사용합니다.

```powershell
git pull --ff-only
.\run.bat
```

기존과 똑같이 `outputs/pet_counts.csv`, `outputs/pet_breeds.csv`와 사진별 `*_pets.jpg`가 저장됩니다. **새로운 `outputs/check_16`이나 `review_19` 폴더를 만들지 않습니다.**

최신 YOLO11m 가중치는 기존 2개 탐지기가 모두 실패한 경우에만 자동 다운로드됩니다(약 41MB, 공식 SHA-256 검증). 실사진에서 검출이 없으면 예측을 만들어 내지 않고 미탐으로 남깁니다.

#### 8. 2026-10-28 — 16번 사모예드 미탐 재보고 및 교차 검토

- 사용자 실제 실행 화면에서 **16번은 계속 Dogs: 0, Cats: 0**. 화면에는 옆모습의 흰 사모예드가 통나무에 일부 가려져 보임.
- 진단 가설: 표준 COCO 사전학습 모델이 다른 동물(예: 양/곰)로 분류했을 수 있으며, 기존 YOLO의 `classes=[15,16]` 필터 때문에 해당 박스가 결과에서 제외될 수 있음. **원래 모델의 전체 클래스 출력 로그가 없으므로 원인 확정은 아님.**
- 마지막 YOLO11m 탐지 단계에 한해 **클래스 사전 필터를 해제**하고 실제로 검출된 다른 동물 박스(곰·양·말·소)가 있으면 ResNet50 37품종 분류와 교차 확인. 낮은 분류 점수는 버리고, 선택되더라도 `review_detection` 표시와 품종 후보만 기록. 마릿수 정확도 계산에서 제외.
- 확대 크롭 탐지에도 같은 원칙을 적용. 기본 `main.py` 실행 흐름과 기존 `outputs` 경로 유지.
- **검증 한계:** 모의 YOLO 박스와 분류기 테스트는 수행 가능하지만, 16번 원본 사진의 실제 YOLO11m 전체 클래스 출력은 현재 실행 환경에서 확인하지 못함. 검출 성공을 단정하지 않으며 재검사 결과로 확인해야 함.

##### 후속 수정: 원인 판별용 실행 로그 보완

- [교차 검토 코드](https://github.com/judanvy8-netizen/ace-pet-vision/commit/c2b817926ef33be1ea8564293efe1e1c3e262096): 마지막 YOLO11m 단계에서 COCO 클래스 필터를 해제하고, 실제 다른 동물 클래스 박스를 37품종 모델로 검토합니다. 허용된 클래스는 bear/sheep/cow/horse이며 품종 점수 0.55 미만이면 채택하지 않습니다.
- [로그 개선](https://github.com/judanvy8-netizen/ace-pet-vision/commit/f08195d86e7aa63e78642588f609d641a35afb06): 여전히 0마리면 `outputs/errors.log`에 YOLO11m 원래 예측한 클래스와 점수를 기록합니다. YOLO11m 가중치 다운로드·실행 실패는 터미널에도 경고를 표시하고 CSV의 `status=partial_error`로 구분합니다.

#### 9. 2026-10-28 — 모델 간 품종·종 충돌 개선

사용자가 제공한 실제 출력 이미지 네 장에서 다음 현상을 관찰했습니다. 04번 벵갈 고양이는 Bengal 약 50%의 저신뢰 검토, 08번 치와와는 YOLO 개 탐지·ResNet 전체 1위 Bengal 33%로 충돌, 16번 사모예드는 다른 동물 클래스 YOLO 박스·Samoyed 82% 검토, 19번 스핑크스는 YOLO 개 판정에도 ResNet Sphynx 95%인 상태였습니다.

##### 오류 원인

- 기존 최종 마릿수는 YOLO가 정한 개/고양이 클래스만 사용했습니다. 그래서 Sphynx라는 강한 품종 증거가 있어도 Dogs:1로 저장했습니다.
- 기존 품종 분류는 37개 전체 중 1위만 표시했습니다. 따라서 실제 개를 탐지했는데도 Bengal 33% 같은 고양이 품종을 개의 후보로 보여줬습니다.
- Bengal '50%' REVIEW는 점수를 정수로 반올림해 표시했기 때문에 실제 임계값 50.0% 미만일 가능성도 있었습니다.

##### 코드 변경과 목적

- `shared/fusion.py`를 새로 작성해 YOLO 원래 종·ResNet 전체 1위 품종·종별 확률합·같은 종의 품종 후보를 분리해서 계산합니다.
- ResNet의 전체 1위 품종이 반대 종이고 점수가 85% 이상이며 그 종 전체 확률합이 90% 이상일 때에만 최종 종을 수정합니다. 수정 사실은 `review_species`로 남겨 검증된 정답과 구분합니다.
- 반대 종의 전체 1위 점수가 낮으면 YOLO가 탐지한 종을 유지하면서 **같은 종에서 최고 점수인 품종 후보**를 보여줍니다. 전체 37종 확률을 종별로 재정규화하지 않아 가짜 고신뢰를 만들지 않습니다.
- `shared/pet_model.py`에서 애매한 예측일 때에만 좌우반전·주변 영역 크롭을 이용한 추가 추론을 수행하고 결과를 평균합니다. 85% 이상 확실한 종 교정 후보는 원래 크롭 근거를 유지합니다.
- `shared/common.py`/`source/main.py`/`shared/visualizer.py`에서 마릿수 계산·표시·CSV에 최종 종과 원래 모델 판단을 모두 저장하고 REVIEW의 원인을 구체적인 문구로 표시합니다. 기존 `main.py` 기본 실행과 `outputs` 폴더는 유지합니다.
- `tests/test_species_fusion.py`에 Sphynx 95%, Chihuahua 사진의 Bengal 33%, Bengal 49.6%, 종 교정·이미지 표시·CSV 반영·원래 다른 동물 라벨 보존 등 **모의 테스트 8개**를 추가했습니다.

별도 환경에서 기존 자동 테스트 16개 및 새 분류 판정 테스트 6개(총 22개)가 통과했고, 옵션 없는 `main()` 실행을 모의한 종 교정·CSV 기록도 통과했습니다. GitHub에는 기존 19개 테스트와 새 8개 테스트가 있으며, **GitHub 저장소의 전체 27개 테스트를 원격 Windows/IntelliJ에서 실행한 결과로 취급하면 안 됩니다.** 실제 모델 가중치를 이 환경에서 내려받지 못해 최신 코드로 원본 20장을 추론한 정확도는 확인 전입니다. 결과 파일명이나 품종 정답을 사용해 개/고양이 판정을 강제한 코드는 없습니다.

- 회의록에 기재하지 않은 사항은 '발언이 없었음'이 아니라 **현재 확인한 내보내기에서 확인되지 않음**을 의미합니다.
- 사진·영상 첨부가 '사진', '동영상'이라고만 남아 있으면 **첨부 안의 내용은 추측하지 않습니다**.
- 단톡방 실명·개인 대화 전문을 공개하지 않고 프로젝트 관련 공통 결론과 역할별 과업만 남깁니다.
- 개인별 실제 코드 수정/시험/발표 담당 확인은 조장이 별도로 검증합니다.
