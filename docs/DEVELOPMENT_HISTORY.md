## 1. 무엇을 만들기로 했나?

교사 원본 과제는 사진 속 **개/고양이 탐지·개수 계산·박스 표시·CSV 저장**이며, Python 3.11·Windows CPU·YOLO11n 사용이 기본입니다. 이후 교사의 **구두 추가 지시**에 따라 단순 개·고양이 구별을 넘어 **37개 품종 분류**를 필수 확장 기능으로 채택했습니다. 원본 Markdown에 품종 분류가 없는 것은 이 때문입니다.

**범위:** 우선 사진 파일 입력 → 사진 속 개·고양이 위치 찾기 → 영역별 37품종 후보 추론 → 결과 이미지·CSV 저장. 카메라·GUI는 후순위. Oxford-IIIT Pet 37품종(고양이 12, 개 25) 범위 밖인 골든 리트리버는 지원 품종이라고 주장하지 않습니다.

## 4. 기술적 선택의 근거

1. **탐지와 품종 분류를 분리:** 사진 하나의 ResNet 품종 분류만으로는 여러 개체 위치·개수를 결정할 수 없습니다. YOLO 박스를 잘라 품종 모델에 전달합니다.
2. **중복 박스 병합:** 얼굴/몸통이 각각 별도 박스로 나오는 사례가 발생해 교집합/합집합 비율(IoU)과 작은 박스 포함률을 확인합니다. 실제로 동물이 서로 겹친 사진에서는 오병합 가능성이 있으므로 사람 검증이 필요합니다.
3. **미탐일 때만 무거운 검사:** YOLO11s와 TTA를 항상 쓰면 구형 Windows CPU에서 느려집니다. 검출 실패 경우에만 추가 실행합니다.
4. **닫힌 37품종 분류의 한계:** ResNet은 37개 중 후보를 강제로 고르므로, 지원 밖 품종 또는 동물이 없는 사진에서도 틀린 답을 낼 수 있습니다. 전체 이미지 분류는 반드시 `review_only`로 표시해 탐지 성공률에 포함하지 않습니다.
5. **사진 출처 열:** 출처를 결과와 함께 표시해 자료 제공자·사용 권한을 추적할 수 있도록 합니다. 출처가 없는 사진은 임의로 채우지 않습니다.

- **모의 단위/통합 테스트:** 기존 13개에 자동 고해상도 재검사·YOLO11m 확대 검사 경로·확대 박스 좌표 복원 테스트 3개를 추가해 **16개 통과**. 검출·분류 모델은 모의 객체를 사용했으므로 **실제 37품종 정확도나 16번 검출 성공을 뜻하지 않음**.
- **사용자 확인 결과:** 05·07번 중복 문제 해결, 19번 추가 검사는 탐지 성공, 16번은 이전 재검사까지 여전히 0마리.
- **다음 실험:** IntelliJ에서 `source/main.py`를 **그냥 Run**하여 16번 사모예드 결과(`outputs/16_dog_samoyed_pets.jpg` 및 CSV의 `detector`) 확인. 자동 YOLO11m·확대 검사도 0마리라면 미탐 사례로 기록하고 모델 성능 개선을 별도 검토. 파일명이나 정답표로 예측을 꾸미지 않음.
- **평가 자료:** `data/ground_truth.csv`의 20장 실제 개수, `test_cases.csv`의 관찰 결과, 동물 없음·혼합/가림 사례, 실패 사례 3개 이유 및 조건을 **사람이 확인하여 기록**해야 함.
- **발표 윤리:** 조장이 통합 구현한 코드라도 팀원별로 실제로 맡아 설명·수정·테스트한 내용을 구별해 제출합니다.

## 6. IntelliJ에서 실행하는 방법 — 별도 옵션이나 결과 폴더 불필요

프로젝트 `C:\KSW\ace-pet-vision`을 IntelliJ에서 열고 `source/main.py` 우클릭 → **Run 'main'** 하면 기본 사진 20장을 자동 분석합니다. 또는 터미널에서 다음 두 명령만 사용합니다.

```powershell

.\run.bat
```

기존과 똑같이 `outputs/pet_counts.csv`, `outputs/pet_breeds.csv`와 사진별 `*_pets.jpg`가 저장됩니다. **새로운 `outputs/check_16`이나 `review_19` 폴더를 만들지 않습니다.**

최신 YOLO11m 가중치는 기존 2개 탐지기가 모두 실패한 경우에만 자동 다운로드됩니다(약 41MB, 공식 SHA-256 검증). 실사진에서 검출이 없으면 예측을 만들어 내지 않고 미탐으로 남깁니다.

## 8. 2026-10-28 — 16번 사모예드 미탐 재보고 및 교차 검토

- 사용자 실제 실행 화면에서 **16번은 계속 Dogs: 0, Cats: 0**. 화면에는 옆모습의 흰 사모예드가 통나무에 일부 가려져 보임.
- 진단 가설: 표준 COCO 사전학습 모델이 다른 동물(예: 양/곰)로 분류했을 수 있으며, 기존 YOLO의 `classes=[15,16]` 필터 때문에 해당 박스가 결과에서 제외될 수 있음. **원래 모델의 전체 클래스 출력 로그가 없으므로 원인 확정은 아님.**
- 마지막 YOLO11m 탐지 단계에 한해 **클래스 사전 필터를 해제**하고 실제로 검출된 다른 동물 박스(곰·양·말·소)가 있으면 ResNet50 37품종 분류와 교차 확인. 낮은 분류 점수는 버리고, 선택되더라도 `review_detection` 표시와 품종 후보만 기록. 마릿수 정확도 계산에서 제외.
- 확대 크롭 탐지에도 같은 원칙을 적용. 기본 `main.py` 실행 흐름과 기존 `outputs` 경로 유지.
- **검증 한계:** 모의 YOLO 박스와 분류기 테스트는 수행 가능하지만, 16번 원본 사진의 실제 YOLO11m 전체 클래스 출력은 현재 실행 환경에서 확인하지 못함. 검출 성공을 단정하지 않으며 재검사 결과로 확인해야 함.
